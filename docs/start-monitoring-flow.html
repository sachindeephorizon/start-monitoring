1. The tap — startSession()

User taps "Start Monitoring" in HomeScreen.tsx:

const monitoring = useMonitoringSession();
monitoring.startSession({ tripType: 'cab' });

Phase A — synchronous (returns instantly, navigates to QuickStart)

#What happens
1Reset refs: sequenceRef=0, sessionIdRef='sm_{timestamp}', tierRef=1, destinationRef=null, autoStoppedRef=false
2Clear stale distance from prior session (SecureStore.deleteItemAsync on distanceM, lastLat, lastLng)
3Write lastCheckinAt to SecureStore (seed for check-in anchor)
4Spawn new TierSignalService() → store in tierServiceRef
5Register tierService.onTierChange() — on tier flip: recompute nextCheckinAt, call reconfigureForTier()
6Compute t1DueIso = startMs + TIER_INTERVAL_MIN[1]
7setState({ isActive: true, startedAt, tier: 1, nextCheckinAt: t1DueIso, ... })

Phase B — deferred async (doesn't block UI)

#CallWhat it does
1Promise.all([SecureStore.setItemAsync(...)])Writes active='true', userId, sessionId, startedAt, tripType, appState, sequence=0 — the bridge to the background task
2entryStart(userId)POST /handling/entry → rewp2 creates sessionStore[userId], calls location_service /tracking/start
3Location.getCurrentPositionAsync({ Balanced })Seed GPS fix, stored in latestLocationRef
4sendPingFromLatestRef.current?.()Fires immediate first ping so /users/active populates fast
5restartBackgroundForTier(1)Registers the background location task (§3)
6startWatcherForTier(1)Starts foreground GPS watcher (§2)
7Location.requestBackgroundPermissionsAsync()Asks for ACCESS_BACKGROUND_LOCATION

2. Foreground flow (app is open)

The GPS watcher

startWatcherForTier(tier) calls Location.watchPositionAsync with per-tier params:

TIER_PROFILES[1] = { accuracy: Lowest,    pingMs: 15000, distanceM: 10, stationaryCooldownMs: 60000 }
TIER_PROFILES[2] = { accuracy: Balanced,  pingMs: 10000, distanceM:  8, stationaryCooldownMs: 30000 }
TIER_PROFILES[3] = { accuracy: High,      pingMs:  5000, distanceM:  4, stationaryCooldownMs:  5000 }

Every watcher callback stores in latestLocationRef and schedules sendPingFromLatest() via pingTimerRef.

sendPingFromLatest() — foreground ping loop

┌──────────────────────────────────────────────────────────────────┐
│ sendPingFromLatest() — runs every T1=15s / T2=10s / T3=5s        │
└──────────────────────────────────────────────────────────────────┘
   │
   ├─▶ [if no loc or no uid → bail, set status=no-fix]
   │
   ├─▶ Feed tier engine FIRST (before cooldown bail)
   │     • distanceToDest = approxDistanceM(loc, destinationRef)
   │     • nearDest = distanceToDest <= 400m
   │     • tierEngine.reportPosition(lat, lng, nearDest)
   │
   ├─▶ AUTO-STOP — if distanceToDest <= 250m && !autoStoppedRef
   │     • autoStoppedRef = true
   │     • endSessionRef.current?.()
   │     • return (skip ping; session is tearing down)
   │
   ├─▶ Stationary cooldown — if !moving && cooldown not elapsed → bail
   │
   ├─▶ Build PingPayload:
   │     { lat, lng, accuracy, speed, heading, timestamp, moving,
   │       source: 'expo-location', appState, sequence: ++seqRef,
   │       gpsIntervalMs, sessionId }
   │
   ├─▶ pingLocation(uid, payload) → POST /:uid/ping ────────┐
   │                                                          │
   ├─◀ response { tier, filtered?, deviationAlert?,           │
   │              inactivityFlag?, arrivalDetected?,          │
   │              missedCheckin? }                            │
   │                                                          │
   ├─▶ Bridge backend signals into local tier engine:         │
   │     deviationAlert.severity === 'long' → pushSignal('long_deviation')
   │     deviationAlert.severity === 'short' → pushSignal('short_deviation')
   │     inactivityFlag → pushSignal('inactivity')
   │     missedCheckin → pushSignal('missed_checkin')
   │                                                          │
   └─▶ setState({ lastLocation, lastDeviation, arrivalDetected,
                  inactivityFlag, hasFirstPing: true, ... })
                                                              │
                                                              ▼
                     rewp2 /:id/ping handler (tracking.ts):
                     1. Kalman filter GPS spikes
                     2. H3 road-snap
                     3. Redis PUBLISH → fanout to websocket dashboards
                     4. Deviation check (H3 corridor, streak counter)
                        • 3 consecutive out → deviationAlert.short
                        • 8 consecutive out → deviationAlert.long
                     5. Inactivity check (10 min < 30m displacement)
                     6. Arrival check (within 200m of dest)
                     7. Return { tier, deviationAlert?, inactivityFlag?,
                                 arrivalDetected?, missedCheckin? }

Polyline + remaining distance

Independent of pings, once a destination is set, remainingTimerRef polls GET /destination/:uid/remaining every 10 s → drives the Route tile.

3. Background flow (app swiped / killed / backgrounded)

Registration

await Location.startLocationUpdatesAsync(MONITORING_BG_TASK, {
  accuracy: BG_ACCURACY_BY_TIER[tier],     // T1=Lowest, T2=Balanced, T3=High
  timeInterval: BG_INTERVAL_BY_TIER[tier], // T1=60s, T2=15s, T3=5s
  distanceInterval: 5,
  foregroundService: {
    notificationTitle: `Deep Horizon · Monitoring · T${tier}`,
    notificationBody: '...',
    notificationColor: '#1d6fa4',
  },
  pausesUpdatesAutomatically: false,
});

This spawns an Android foreground service with a persistent notification — that's what keeps the process alive when the app is backgrounded. AndroidManifest sets android:stopWithTask="false" on LocationTaskService, so even swipe-from-Recents leaves the service running.

Task definition — TaskManager.defineTask(MONITORING_BG_TASK, …)

Runs in an isolated JS context (no React, no state, no navigation):

OS delivers batched locations ──▶ backgroundTaskCallback({ data: { locations }, error })
    │
    ├─▶ Read gate from SecureStore: BG_KEYS.active === 'true' ? (else no-op)
    │
    ├─▶ Read bridge: userId, sessionId, appState, sequence
    │
    ├─▶ For each location (sorted chronologically):
    │     1. sequence++
    │     2. updateTraveledDistance(lat, lng, accuracy)
    │     3. pingLocation(userId, {
    │          ...payload,
    │          source: 'background_task',    ← distinguishable
    │          appState,
    │          sequence,
    │        })
    │
    └─▶ SecureStore.setItemAsync(BG_KEYS.sequence, String(sequence))

Key fact: the background task uses the same POST /:uid/ping endpoint as the foreground. The only difference is the source and appState fields in the payload.

Why it works on stock Android and fails on ColorOS

OSBehavior
Stock Android, PixelForeground service keeps process alive indefinitely. Pings continue.
Most OEMsSame, with minor Doze coalescing below 15 s cadence.
ColorOS (Oppo/Realme/OnePlus)Kills process on swipe despite stopWithTask="false". Requires user to enable "Allow background activity" + pin in Recents.

Rehydration on cold restart

BootGuard finishes → userId set → rehydrate effect in MonitoringSession.tsx:
    1. Read BG_KEYS.active, userId, sessionId, startedAt, tripType
    2. If active==='true' AND Location.hasStartedLocationUpdatesAsync(MONITORING_BG_TASK)===true
    3. Read nextCheckinAt, lastCheckinAt, destinationLat/Lng/Name
    4. Spawn new TierSignalService, restore lastCheckinAtRef, destinationRef
    5. setState({ isActive: true, destination: restored, nextCheckinAt, ... })
    6. startWatcherForTier(1) (for foreground UI — BG is already running)
    7. If destination restored → re-fetch polyline via GET /destination/:uid,
                                 re-arm remaining poll

4. Check-in flow

Countdown source

state.nextCheckinAt (ISO string) is the single source of truth. Computed from:

  • Session start: startedAt + TIER_INTERVAL_MIN[1]
  • Tier shift: lastCheckinAt + TIER_INTERVAL_MIN[newTier]
  • Successful response: advances via applyCheckinUpdate

CheckInWatcher.tsx — mounted once at top of nav tree

Path A — Foreground tick (every 1 s):

if (isActive && !inEscalation):
  if now > dueMs + 30s:  pushSignal('missed_checkin') + navigate Escalation
  elif now > dueMs:      navigate CheckInPrompt  (modal with 30s countdown)

Path B — Background notifications (AlarmManager via expo-notifications):

On every nextCheckinAt change:
  cancelPending()
  schedule prompt notification  at dueDate         (channelId='monitoring')
  schedule missed notification  at dueDate + 30s

Tap listener (Notifications.addNotificationResponseReceivedListener):

  • type === 'monitoring_checkin' → navigate to CheckInPrompt
  • type === 'monitoring_checkin_missed' → pushSignal('missed_checkin') + navigate Escalation

User responds "Safe"

CheckInPromptScreen → checkinRespond(uid, true) → POST /handling/checkin/:uid/respond:

rewp2:
  session.last_response = 'safe'
  if tier > 1: shiftTier(session, 1, 'user_confirmed_safe')
  session.next_checkin_at = now + interval
  response: { tier: 1, next_checkin_at, ... }

User responds "I Need Help" OR misses window

  • "Need Help" → POST /handling/checkin/:uid/respond { is_safe: false } → shiftTier(3, 'user_needs_help') + dispatchToSoc('user_needs_help')
  • Missed → POST /handling/checkin/:uid/missed → shiftTier(3, 'missed_checkin') + dispatchToSoc('checkin_missed') + trigger_escalation: true in response

5. Tier engine — tierSignal.ts

Local, client-side, drives GPS strategy without waiting for backend.

Signals

type SignalType = 'inactivity' | 'short_deviation' | 'long_deviation'
                | 'missed_checkin' | 'user_needs_help'

Rules

tier = 3 if  active.has('long_deviation') | active.has('missed_checkin') | active.has('user_needs_help')
     = 2 if  active.has('short_deviation') | active.has('inactivity')
     = 1 otherwise

Inactivity detector

  • INACTIVITY_WINDOW_MS = 10 min, INACTIVITY_DISTANCE_M = 30 m
  • Anchor-based: while within 30 m of anchor, dwell; if now - anchor.since >= 10 min → push 'inactivity'
  • Suppressed when nearDest === true (within 400 m of destination)

On tier change

tierService.onTierChange((newTier, reason, prev) => {
  reconfigureForTier(newTier)  // restart BG task + foreground watcher with new params
  setState({ tier: newTier, intervalMinutes: TIER_INTERVAL_MIN[newTier], nextCheckinAt: ... })
})

6. Auto-stop on arrival (250 m)

In sendPingFromLatest:

if destinationRef && distanceToDest <= 250 && !autoStoppedRef:
  autoStoppedRef = true
  endSessionRef.current?.()   // latched — won't re-fire

Reset on startSession() and setDestination(). Destination is persisted to SecureStore so this works after cold restart.

7. endSession() — teardown

stopWatchersInternal()                             ← stops FG watcher + ping timer + tier engine
setState({ isActive: false, nextCheckinAt: null, destination: null, ... })
SecureStore.setItemAsync(BG_KEYS.active, 'false')  ← gates BG task (silent no-op on delivery)
SecureStore.deleteItemAsync(startedAt, tripType, nextCheckinAt, lastCheckinAt,
                             destinationLat, destinationLng, destinationName)
Location.stopLocationUpdatesAsync(MONITORING_BG_TASK)   ← kills the foreground service
entryEnd(userId)                                   ← PUT /handling/entry/:uid/end
stopTracking(userId)                               ← POST /:uid/stop → saves session + logs
